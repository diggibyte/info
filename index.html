Employee Upskilling Program

8 weeks to build with agentic AI, not just talk about it.

Every team here already knows how to build reliable systems: that is the job. What is changing is the tooling. Agentic AI is becoming a normal part of how that work gets done, not an experiment on the side. This program exists so that shift happens deliberately, with real skill behind it, instead of piecemeal and reactive.

The goal is not to make everyone an AI researcher. It is to make sure that when a customer asks if something can be faster, cheaper, or more reliable, the answer is yes, because the team building it knows how to put agents to work on real data, real pipelines, and real decisions, safely and with the right guardrails in place.

A hands-on program for Data Engineering, AI/ML, BI, and Platform teams. Every week ends with something working: not a slide, an artifact you actually built.

The Weekly Journey

Every week has a clear objective: learn one capability, build one working artifact, and show evidence of business value.

Phase 1 · Weeks 1–3
Core FoundationAll roles

These three weeks create the same baseline for everyone. By the end of Week 3, every participant has the shared AI skills needed to confidently move into a role-specific build.

Week 1: AI-Native Ways of Working · ~4 hrs

  • Learn: prompting, context engineering, secure coding practices with AI tools.
  • Course: Claude Code quickstart.
  • Hands-on: use an AI coding assistant in your IDE on a real backlog item; try MCP in VS Code, local Codex workflows, or Claude Code, and compare how tool access changes the quality of outputs.
  • Build: use an AI coding assistant on one real backlog task this week.
  • Evaluated by: this feeds the "AI awareness and adoption" impact dimension in Week 8.

Week 2: GenAI & RAG Foundations · ~5 hrs

  • Learn: LLM/GenAI basics, embeddings, RAG, structured outputs, and model selection.
  • Course: Building GenAI apps on Databricks and Building & Evaluating Advanced RAG.
  • Build: a basic RAG application over an internal document set.
  • Evaluated by: this RAG app becomes the base you build on in Weeks 4–5; keep it and improve it.

Week 3: Agent Architecture & Tooling · ~5–6 hrs

  • Learn: agent design patterns, tool calling, MCP, memory, and human-in-the-loop controls.
  • Course: Mosaic AI Agent Framework, MCP documentation, and Databricks Genie / IDE-connected agent patterns.
  • Hands-on: connect an agent to local or cloud tools using MCP; include a Databricks Genie or service connection in the flow so the agent can read context from your environment instead of acting in a vacuum.
  • Build: your first agent that calls at least 3 tools.
  • Evaluated by: this agent becomes the foundation you specialize into your role's assignment next.
Phase outcome: everyone finishes with three working artifacts — an AI-assisted task, a RAG app, and a 3-tool agent.
Phase 2 · Weeks 4–5
Role SpecializationYour role track

Weeks 4–5 are where the program becomes specific to what a Data Engineer, BI Engineer, Data Scientist, or Platform Engineer actually needs to deliver.

Week 4: Track Deep Dive

  • Learn: the domain-specific patterns for your role: pipelines for DE, semantic modeling for BI, orchestration for DS, or governance + platform patterns for Platform.
  • Course: use the role-specific learning path linked in the track cards below.
  • Build: design the architecture for the Week 5 assignment.

Week 5: Role Agent Implementation

  • Build: the working, role-specific agent defined in your track.
  • Evaluate: this is the artifact you carry into Weeks 6–8; it does not get rebuilt later, only strengthened.
Phase outcome: a working agent that solves a real problem in your domain, not a generic exercise.
Phase 3 · Weeks 6–7
Production & Real-World ApplicationShared process

This is where the work becomes trustworthy, measurable, and useful outside a lab. The goal is not a demo; it is a governed system that solves a real stakeholder problem.

Week 6: Production Agent Engineering · ~5 hrs

  • Learn: evaluation methodology, guardrails, Unity Catalog access, MLflow tracing, cost and latency control.
  • Course: Agent evaluations, MLflow tracing, and Unity Catalog governance.
  • Build: add an evaluation report, guardrails, and a cost/latency view to your Week 5 agent.
  • Evaluated by: this directly produces your "Governance contribution" evidence for Week 8.

Week 7: Customer / Team Use Case Sprint · ~5–6 hrs

  • Do: pick one real, currently unsolved problem with a manager or PM and apply your agent to it.
  • Build: a working accelerator a real stakeholder has confirmed helps them.
  • Evaluated by: this produces your "Customer value" and "Delivery improvement" evidence.
Phase outcome: your agent is now trustworthy, measured, and validated against a real problem, not a prototype-only demo.
Phase 4 · Week 8
Evaluation & ShowcaseFinal proof

Week 8 is where you present the evidence that your work matters. This is not an attendance check; it is a demonstration of impact and technical judgment.

  • Do: deliver a live 10–15 minute demo of your working system — no slides, no screenshots.
  • Present evidence for all six impact dimensions: customer value, delivery improvement, AI awareness/adoption, governance/cost, knowledge sharing, and technical defense of your design choices.
  • Outcome: certification tier assigned based on demonstrated impact, not attendance.
Outcome: a credible, measurable demo backed by artifacts, design decisions, and real stakeholder value.

Weeks 4–5 · Role Tracks

Same two weeks, different destination. Pick the track that matches your role and the outcome you need to ship.

Mandatory Toolchain
Databricks AI Dev Toolkit + MCP + IDE agent workflows

All Data Engineers, Data Scientists, and BI Engineers should complete the Databricks AI Dev Toolkit, learn MCP in VS Code or a coding agent, and understand how to connect Databricks Genie, services, or internal tools from the IDE.

Mandatory: Databricks AI Dev Toolkit; MCP for VS Code or equivalent IDE tooling; either OpenAI or Anthropic governance training based on the model stack being used.
Data Engineers
→ Agentic Data Engineers

What you will learn

  • MCP / tool development
  • RAG data pipelines
  • Structured + unstructured ingestion
  • Metadata & context engineering
  • Lakeflow, Delta & Unity Catalog
  • Automated data-quality agents
What good looks like
  • You can connect an agent to real data sources and tools without losing control of the workflow.
  • Your agent detects pipeline issues, explains likely root cause, and recommends or executes the right remediation.
  • You understand lineage, quality checks, access boundaries, and the cost of each action.
Mandatory: Databricks AI Dev Toolkit, MCP for VS Code, and local coding agent workflows.
Course: Databricks Lakeflow docs, Unity Catalog governance, and agent tooling.
Build: an Autonomous Data Pipeline Agent that detects issues, diagnoses root cause, checks lineage and quality, and recommends or safely executes remediation.
Evaluate: did the agent act on the right signal, reduce manual triage, and explain the decision path clearly?
Data Scientists
→ Agentic AI Engineers

What you will learn

  • Advanced RAG, embeddings & reranking
  • Tool calling & memory
  • Agent orchestration, multi-agent patterns
  • Model selection
  • Evaluation & hallucination testing
  • Guardrails & MLflow
What good looks like
  • Your agent answers real business questions with grounded evidence and clear reasoning.
  • You can validate model output against source facts and explain the answer path.
  • Your workflow is measurable: accuracy, grounding, explainability, and usefulness all matter.
Mandatory: Databricks AI Dev Toolkit, MCP for IDE tooling, and service access patterns using Databricks Genie or connected tools.
Course: advanced RAG, agent evals, and MLflow tracing.
Build: a multi-agent business analyst: planner, researcher/data agent, reasoning/analysis agent, and validation agent.
Evaluate: how accurate, grounded, and explainable was the final answer under real business questions?
BI Engineers
→ AI/BI Engineers

What you will learn

  • Semantic modeling & trusted metrics
  • Genie / AI-BI
  • NL → SQL validation
  • Conversational analytics
  • Proactive insight generation
  • Action-oriented analytical agents
What good looks like
  • Your agent can answer a business question in plain language and connect the answer to trusted metrics.
  • The answer explains the business story instead of only showing a chart or table.
  • A stakeholder can trust the result without needing a data analyst to validate every step.
Mandatory: Databricks AI Dev Toolkit, GenAI-enabled BI workflows, and MCP / IDE connectivity for data and service access.
Course: semantic modeling, AI-BI patterns, and natural-language analytics workflows.
Build: an agent that answers questions like "Why did gross margin decline?" by investigating drivers, explaining the trend, and recommending next steps.
Evaluate: could a business stakeholder trust the answer without needing a data analyst to validate every step?
Platform Engineers
→ Agentic Platform Engineers

What you will learn

  • Model serving & AI Gateway
  • MCP infrastructure
  • Identity & authorization
  • Unity Catalog governance & secrets
  • CI/CD, tracing & observability
  • Model routing, cost management, AgentOps
What good looks like
  • Your solution is secure, observable, and ready for real team adoption.
  • You can explain access boundaries, model routing, logging, and operational guardrails.
  • You have built something reusable that helps other teams ship AI workflows more safely and consistently.
Course: model serving, governance, and secure platform architecture for autonomous tools.
Build: a reusable Agent Platform Blueprint that other Diggibyte teams can deploy against.
Evaluate: does the solution scale securely, remain observable, and keep model cost and access under control?

Demonstrating Your Impact

Week 8 is not a scored exam. You show real, evidence-based impact across six dimensions, reviewed in a live demo.

DimensionWhat you must show
Customer value deliveredA clear before and after picture: what changed for a customer or internal stakeholder because of the agent or tool you built, described in plain terms a non-technical reviewer can understand.
Delivery improvementEvidence that your work reduced production issues: fewer bugs pushed, bugs caught before release, or a PM/reviewer sign-off confirming the improvement in delivery quality.
AI awareness and adoptionProof that you applied AI-native practices in your daily work, plus any contribution to spreading that awareness: a blog post written, an internal session or seminar delivered, or an external talk given.
Governance contributionDemonstrated understanding of cost and token usage: you can explain how you measured token consumption and what specific technique you used to reduce it (for example prompt trimming, caching, smaller model routing, or batching).
Knowledge sharingWhether your work was documented clearly enough that another team member could reuse it without asking you questions.
